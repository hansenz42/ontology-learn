# 如何使用本体（Ontology）做企业知识管理

企业把内部文档接入检索增强生成（RAG）之后，员工已经可以提问、找材料、核对引用。接下来的问题是：当立项提案与发行记录说的是两回事，知识助手怎样回答“哪些作品由林青执导”，编目团队和报表系统又怎样得到同一份清单？

这套中文教程面向企业知识管理负责人、业务专家和实施团队。我们从媒体企业的这个问题出发，学习怎样用本体明确业务概念，把分散的材料整理成有版本、有证据、可审核的事实，再让检索和问答使用这些事实。

## 学习路线

| 阶段 | 需要回答的问题 | 对应章节 |
| --- | --- | --- |
| 从现状到问题 | RAG、LLM Wiki 和业务表怎样组织知识？哪些错答值得用本体处理？ | 1–3 |
| 建模与抽取 | 怎样从 CQ 建模并整合旧模型，管理权威记录和术语，把候选事实审核为正式记录？ | 4–7 |
| 查询与验证 | 怎样把 SPARQL 接入现有检索，用 PROV-O 追来源，并定位错答？ | 8–10 |
| 治理与交付 | 怎样维护概念与数据，验收并重建第一版知识库？ | 11–12 |

前三章正文已发布，第 4–12 章目前为教学规划。案例的设计背景见[媒体文化企业本体知识系统草案](媒体文化企业本体知识系统-建设与抽取流程说明.md)。
