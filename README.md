# 如何使用本体（Ontology）做企业知识管理

企业把内部文档接入检索增强生成（RAG）之后，员工已经可以提问、找材料、核对引用。接下来的问题是：当立项提案与发行记录说的是两回事，知识助手怎样回答“哪些作品由林青执导”，编目团队和报表系统又怎样得到同一份清单？

这套中文教程面向企业知识管理负责人、业务专家和实施团队。我们从媒体企业的这个问题出发，学习怎样用本体明确业务概念，把分散的材料整理成有版本、有证据、可审核的事实，再让检索和问答使用这些事实。

## 从这里开始

1. 阅读[导论 · 企业 RAG 已经找到了文件，为什么还会答错？](docs/00-企业RAG与本体.md)，用三条材料判断什么时候值得建模。无需编程。
2. 进入[第一课 · 一个人可以有几个角色？](docs/01-从问题到模型.md)，在仓库根目录运行 `python3 examples/media/roles.py 导演`，检验第一个建模决定。实验只需 Python 3。
3. 查看[十二章教学大纲与阅读清单](tutorial-planning/本体驱动的知识工程开源教程-教学大纲与资料清单.md)。

## 学习路线

| 阶段 | 需要回答的问题 | 对应章节 |
| --- | --- | --- |
| 确定范围与建模 | 系统应回答哪些问题？作品、版本、文件和参与角色如何区分？ | 1–4 |
| 表达与验证 | 怎样用 RDF 表达事实、用 SPARQL 查询、用 SKOS 管理术语、用 OWL 推理、用 SHACL 校验？ | 5–8 |
| 证据与应用 | 怎样审核抽取结果、处理冲突、管理版本，并评价知识应用？ | 9–12 |

目前可学习的是企业 RAG 导论、入门课和配套实验，十二章完整课程仍在编写规划中。案例的设计背景见[媒体文化企业本体知识系统草案](媒体文化企业本体知识系统-建设与抽取流程说明.md)。
