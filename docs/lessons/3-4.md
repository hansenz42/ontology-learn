# 3.4 哪些情况值得投入知识工程？
假设团队只有两个小时处理一个需求。第一种需求是找到某部作品片尾的准确时间码；第二种是让每个月的导演报表和对外知识助手都按同一口径出清单。两项都需要证据，但值得投入的工作不同。

## 比较两种投入
对于定位文件，补齐索引、版本和时间码后，编辑可以自己验证。新建一套角色模型未必节省更多时间。对于周期性清单，编目、报表、问答都得区分拟邀、署名和角色；每个系统自行解释一次，产生分歧后还得重新核对。在这个条件下，记录一次共同的定义、把来源与角色关联起来，就有了复用价值。

复用也有代价。谁有资格解释版本？原件能否持续访问？谁来审同名人物、批准术语变更？如果缺少这些条件，模型可以漂亮地表达一个尚无证据支持的结论。写试点建议时，应把哪些问题暂缓、需要谁补证也写清楚。

## 交付第三章的决定
把前三章的结果放在一起：第一章的入库图，第二章的失败样例表，第三章的四张卡片和查询结果。写一段试点决定：为“按发行署名产生导演清单”维护最小模型，由编目员负责片尾核对；把未收录版本列为未知；保留一次性文件定位给检索系统处理。下一章把这段决定转化为可验收的能力问题。

## 思考
如果报表每年只做一次，维护角色词表却需要每周审核，你会继续还是暂缓？先列出还缺哪些数据，再给出决定和触发重新评估的条件。

**自查。** 参考判断：记录查证次数、误答影响、审核工时和材料覆盖情况。若目前每年一次且人工核对很便宜，可以暂缓；若改为跨部门月报，再以同样指标重新评估。
