# 1.5 Agent 该读哪种工具，又该写到哪里？
现在给助手三个工具：查编目表、搜索原文、更新 Wiki。Agent 可以根据任务选择工具、解释返回值并决定下一步。要判断选择是否合理，先把任务拆成两项：用户想知道什么，用户是否要求改变数据。

## 同一句话的不同任务
“片尾在什么位置？”可以先查表取得作品和版本，再从原文索引取回时间码。“林青参与过哪些作品？”先筛选已登记的参与记录，再核对每个返回项的来源。“把这条新提案整理进人物页”则涉及写入：读 B、检查已有页、保留拟邀措辞、写入立项栏，并记录修改依据。

做一个纸上实验。编辑有权读提案和片尾，外包同事只可读公开片尾。两人问同一道发行署名题。给每人画出能访问的材料集合，再决定是否调用页面更新工具。读者只是提问时，可以直接完成查询；把推测写入共享页面会让一次解释变成下次查询的数据。

## 交付第一章的图
画四列：原件、组织方式、查询入口、可能写入的对象。把 A 的片尾放进原件列，把片段索引和片尾表放进第二列，把检索和表查询放进第三列，把人物页放进第四列。画出从人物页回到 A 的线，并给每次读写注明身份。保留一次查询的输入和候选结果。到第二章，这张图会告诉你应该去哪个位置查错。

## 思考
如果工具用管理员身份能读到 B，而调用人没有权限，能否仅靠生成答案时“不要提 B”的提示保护它？尝试把限制放在读取和返回数据的环节。

**自查。** 参考判断：执行工具之前先确定调用人的可见范围，读取和派生页面也应服从相应规则。给两个身份分别手写实际收到的片段列表，再核对最终引用。

## Q&A
**一个助手需要把所有资料搬进同一个数据库吗？** 本例中三种工具可以使用原有存储。关键在于有稳定标识、明确的返回字段、可见范围和来源定位。
