# 1.2 一份提案怎样进入 RAG 索引？
想象编辑把提案 B 放进共享目录，随后问助手“谁曾被拟邀执导《城市回声》”。上传成功只说明文件进了目录。要让检索找到第 2 页的那句话，还要经过解析、分块和索引。

## 跟踪一个片段
解析把版面中的文本和位置读出来。分块决定哪些文字一起成为检索单元。假设“拟邀人员”在表头，“林青｜导演”在下一行。如果只取后一行，即便文字识别完全正确，片段也丢掉了决定含义的表头。给分块结果做一次人工检查：单独拿出这个片段，读者还能看出它描述的是计划吗？

可以把片段登记为 B-02：正文包括表头和行内容，元数据包括原件 B、版本、页码、文档类型及可见范围。关键词索引可以按片名和姓名查找；向量检索可以为意思相近但措辞不同的提问找到候选片段。两种检索都还需要原件位置来核对含义。

## 改一处，再观察影响
设提案第 3 版把拟邀对象换了人。如果只上传新文件，旧片段仍可能出现在结果中。写下两种查询的需求：“当前拟邀谁”要看当前版本，“旧提案拟邀谁”却需要历史版本。重建索引时保留版本信息，才能分别测试这两种需求。

本节的产物是一条可回查的索引记录。请逐项指出：检索依据哪些内容排序？按什么字段过滤？读者点击引用时打开哪里？缺任何一项，都能具体说明它影响哪个操作。

## 思考
若 A 从未被解析成片段，扩大返回条数能不能找回它？先区分原件存在、片段存在和片段排名靠后三种状态。

**自查。** 参考判断：A 在库中但缺少片段，要回查解析与入索引日志；A 有片段且排名靠后，才值得调整召回。把这两个案例的第一处缺失分别圈出。

## Q&A
**向量里已经保存了原句吗？** 运维时应保留原文或可靠的回查地址。向量用于相似度比较，单凭相似度无法核对片尾的实际署名。
