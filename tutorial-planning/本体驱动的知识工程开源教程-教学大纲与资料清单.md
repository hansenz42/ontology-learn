# 本体驱动的知识工程开源教程：教学大纲与资料清单

> 日期：2026-11-07  
> 状态：规划草案  
> 建议名称：《从本体建模到知识工程：构建可验证、可追溯的知识系统》

## 1. 教程定位

面向有基本编程经验、希望建设领域知识库的开发者和业务建模人员，围绕一个完整案例，学习从领域分析、本体建模到知识抽取、验证、溯源和应用的工程流程。

“从本体论出发”的核心是：领域里有哪些对象，它们如何保持身份、发生关系和随时间变化；我们依据什么知道这些事实。教程将这些判断落实为模型、数据和程序。

学习者完成教程后，应能够：

- 根据业务问题确定知识系统的范围与验收标准。
- 解释类、实例、角色、事件、版本等建模选择。
- 使用 RDF、OWL、SKOS 表达领域模型与知识。
- 使用 SPARQL 查询知识，使用 SHACL 检查数据。
- 从材料中产生带证据的候选知识，处理消歧、冲突和审核。
- 管理本体、词表、数据的版本，并交付可重复构建的知识应用。

## 2. 贯穿案例

以媒体文化领域为案例，逐步构建包含作品、版本、素材文件、人物、机构、参与角色、主题和证据的知识系统。

可参考已有的《媒体文化企业本体知识系统：建设与抽取流程说明》。该文档目前属于概念设计草案，教程中应将其作为待验证的建模起点，不将其描述为已经实施的系统。

代表性问题：

1. 某文化主题关联哪些作品、人物和机构？
2. 某作品有哪些版本，分别对应哪些素材文件？
3. 某人物以什么角色参与了哪些作品？
4. 两条同名人物记录是否指向同一个人？
5. 某项事实来自哪份材料、哪个版本、哪个位置？
6. 来源发生冲突时，系统当前采用什么结论，依据是什么？

## 3. 教学大纲

建议设置 12 章，每章交付可以检查的产物。

| 章节 | 核心问题与内容 | 学习产物 |
|---|---|---|
| 1. 为什么需要本体 | 本体、分类体系、数据库模式、知识图谱的关系；哪些场景值得引入本体 | 项目目标与适用性判断 |
| 2. 从业务问题确定边界 | 能力问题（CQ）：系统应该回答什么；范围、反例、参考答案 | 10 个能力问题及验收标准 |
| 3. 学会作出本体判断 | 类与实例、对象与事件、角色与类型、部分与整体、身份与时间 | 概念表与建模决策记录 |
| 4. 建立最小领域模型 | 作品、版本、文件如何区分；人物如何以某个角色参与作品；复用已有模型 | 第一版本体及实例 |
| 5. 用 RDF 表达与查询知识 | IRI、三元组、字面量、Turtle；SPARQL 基础；映射到常见数据库的思路 | 可加载、可查询的小型知识库 |
| 6. 用 SKOS 管理术语 | 名称与概念分离；别名、多语言、上下位、词表映射 | 主题与角色词表 |
| 7. 用 OWL 表达语义与推理 | 类、公理、等价与互斥；开放世界假设；一致性与推理边界 | 能产生预期推论的模型与反例 |
| 8. 用 SHACL 检查数据质量 | 必填、数量、类型、范围；区分逻辑推理、结构校验和事实核验 | 正反测试数据与校验报告 |
| 9. 从资料到候选知识 | 表格映射、文档抽取、LLM 辅助；实体消歧；新事实与模型变更分流 | 带证据的候选知识集 |
| 10. 来源、冲突与审核 | PROV-O；来源版本、证据位置、不同说法；候选与正式结果分离 | 可追溯的事实与审核记录 |
| 11. 版本演进与团队协作 | 本体、词表、数据分别版本化；变更影响、迁移、自动检查、发布 | 可重复构建的知识库版本 |
| 12. 完成知识应用并评估 | 查询、检索、带引用问答；比较纯文本检索和本体辅助方案 | 演示应用与评估报告 |

### 3.1 教学原则

**哲学概念落到具体判断。** 例如：“导演”是人物永久所属的类别，还是一次参与活动中的角色？同一作品换了文件格式，是否成为新作品？

**先建立正确样例，再扩大自动化。** 先手工构建少量模型和数据，明确正确结果，再引入 LLM 批量抽取。

**每章包含失败案例。** 例如同名人物误合并、把版本当成作品、数据校验通过但事实错误、来源撤回后仍被引用。

**区分不同层次的正确性。** 语法可解析、数据满足约束、逻辑一致、事实有证据、业务问题得到回答，应分别验证。

### 3.2 每章统一结构

1. 业务问题与学习目标。
2. 必要概念。
3. 建模选择及理由。
4. 可运行实验。
5. 反例与常见错误。
6. 验收方法。
7. 延伸阅读。

### 3.3 进阶选读

- 上层本体及其适用边界。
- 描述逻辑与形式化推理。
- 本体设计模式与跨领域复用。
- 本体对齐、实体链接与映射维护。
- 大规模知识图谱与推理性能。
- 本体辅助检索、问答与 Agent 应用。

## 4. 开源材料与开放阅读资料

以下清单区分教材、标准、工具和数据。免费阅读不等于允许全文转载；软件许可也不能自动用于其所有外部教材与数据。实际收入仓库时，应记录对应版本和许可。

| 材料 | 教程中的用途 | 收集建议 |
|---|---|---|
| [Maria Keet：An Introduction to Ontology Engineering](https://people.cs.uct.ac.za/~mkeet/files/OEbook.pdf) | 本体基础、逻辑、开发方法及练习 | 优先级最高的理论底稿。已核对的 v1.5（2020）标注 CC BY 4.0，可按许可署名改编；固定具体版本 |
| [LOT Methodology / LOT-resources](https://github.com/oeg-upm/LOT-resources) | 从需求到本体开发的流程，尤其是需求规格文档模板 | 优先收集模板。仓库标注 CC BY-SA 4.0，改编材料保留相应许可与来源 |
| [Knowledge Graphs — Hogan 等](https://kgbook.org/) | 知识图谱整体知识地图，补充查询、构建、推理等背景 | 有免费 HTML 版及配套资源；先作为阅读链接，不能据此推定可以整本搬运 |
| [W3C RDF 1.1 Primer](https://www.w3.org/TR/rdf11-primer/) | RDF 表达基础 | 挑选阅读段落，配上自行编写的中文案例；明确所采用的规范版本 |
| [W3C OWL Primer](https://www.w3.org/TR/owl-primer/) | OWL 语义、建模与推理基础 | 用作语义依据，工具安装说明另行核对 |
| [W3C SKOS Primer](https://www.w3.org/TR/skos-primer/) | 术语、分类和概念映射 | 配合文化主题词表和参与角色词表实验 |
| [W3C SHACL](https://www.w3.org/TR/shacl/) | 数据约束与校验 | 配合有效、无效两组样例数据；标准资料单独标注使用条款 |
| [W3C PROV-O](https://www.w3.org/TR/prov-o/) | 来源与加工过程 | 用于证据链章节，明确项目自定义的证据定位和审核字段 |
| [Protégé](https://github.com/protegeproject/protege) | 可视化编辑 OWL 本体，观察建模和推理结果 | 适合作为建模实验工具；项目声明 BSD-2-Clause |
| [RDFLib](https://github.com/RDFLib/rdflib) | Python 加载、处理和查询 RDF | 适合作为默认实验基础；收入代码时记录版本与许可 |
| [pySHACL](https://github.com/RDFLib/pySHACL) | 执行 SHACL 校验 | 用于分章实验与自动验收；记录版本与许可 |
| [Oxigraph](https://github.com/oxigraph/oxigraph) | SPARQL 图数据库 | 在应用章节引入，前几章可以先用 RDFLib 完成 |
| [WIDOCO](https://github.com/dgarijo/Widoco) | 根据本体生成文档网站 | 用于发布章节，交付可阅读的模型文档 |
| [Ontology Development Kit](https://github.com/INCATools/ontology-development-kit) | 本体生命周期与工程化管理 | 作为进阶参考，研究项目组织和发布流程 |
| [Wikidata](https://www.wikidata.org/wiki/Wikidata:Licensing) | 真实实体、外部标识及对齐实验 | 结构化数据采用 CC0；选小规模固定快照，避免实验依赖实时查询；图片和外部链接内容另行核对 |
| [GSA guides_4_AIagents](https://github.com/GSA/guides_4_AIagents) | 能力问题、本体构建、知识图谱和溯源的任务指南 | 用于 Agent 实验的辅助阅读。仓库标注仍在开发，不作为标准或唯一教材；转载前核对具体材料许可 |

### 4.1 优先整理顺序

1. **Keet 教材**：支撑本体基础与建模判断。
2. **LOT 模板**：支撑需求、范围和开发流程。
3. **W3C 标准与入门文档**：支撑语义和约束的准确性。
4. **RDFLib 与 pySHACL**：形成可运行、可验收的实验。
5. **Wikidata 小规模样本**：补充真实数据与实体对齐练习。
6. **WIDOCO 与 Ontology Development Kit**：完善文档、版本和发布实践。

### 4.2 材料登记字段

- 名称、作者或维护组织。
- 原始链接与获取日期。

- 许可及许可来源链接。
- 对应章节与学习用途。
- 收集方式：仅链接、节选、翻译、改编或代码依赖。
- 修改内容与署名信息。
- 核验状态与待确认事项。

## 6. 第一版最小交付范围

先完成一个小而完整的案例，再扩展章节和数据规模。

### 6.1 样例规模

- 约 30 个实体。
- 10 个业务问题与参考答案。
- 一份作品表。
- 几篇自行编写的说明文档。
- 一份模拟字幕。
- 一套本体、角色词表与主题词表。

### 6.2 必须覆盖的异常

- 同名人物不能直接合并。
- 同一作品存在多个版本。
- 两个来源给出冲突日期。
- 候选事实缺少证据位置。
- 结构校验通过，但事实与来源不符。
- 来源更正后，依赖事实需要重新审核。

### 6.3 完整学习流程

建模 → 导入 → 查询 → 校验 → 追溯 → 修正。

### 6.4 验收标准

1. 学习者可按照文档加载样例并执行查询。
2. 能力问题对应明确的查询或检查方法及预期答案。
3. 故意设计的无效数据能触发相应校验错误。
4. 正式事实能追到具体来源版本和证据位置。
5. 候选、未决冲突和正式结果能够区分。
6. 修正模型或数据后，可以重新执行检查并比较结果。
7. 关键建模选择有理由和反例，学习者能解释为何采用该设计。

## 7. 教程的核心特色

把“如何认识和划分领域”与“如何维护可信知识”连接起来。学习者既能解释建模选择，也能拿出查询、证据和测试，验证知识系统是否回答了最初的业务问题。
