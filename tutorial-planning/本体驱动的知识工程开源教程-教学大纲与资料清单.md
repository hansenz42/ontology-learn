# 本体驱动的知识工程开源教程：教学大纲与资料清单

> 更新日期：2026-11-10
>
> 状态：规划草案  
> 课程名称：《本体论入门指南》

## 1. 教程定位

这是一份知识工程教程。你会从手里的文档出发，用本体建模，再动手构建和验证知识库。入门可以从日常问题和几份文档开始，后续实验再用代码查询和验证模型。

第一章用社区图书馆的例子比较三种检索方法。从第二章起，用署名档案观察身份、角色和版本如何影响答案，尝试建立最小本体，再用同一批问题检查建模带来的变化。

学习者完成教程后，应能够：

- 根据业务问题确定知识系统的范围与验收标准。
- 解释类、实例、角色、事件、版本等建模选择。
- 使用 RDF、OWL、SKOS 表达领域模型与知识。
- 使用 SPARQL 查询知识，使用 SHACL 检查数据。
- 从材料中产生带证据的候选知识，处理消歧、冲突和审核。
- 管理本体、词表、数据的版本，并交付可重复构建的知识应用。

## 2. 贯穿案例

以媒体文化领域为案例，逐步构建包含作品、版本、素材文件、人物、机构、参与角色、主题和证据的知识系统。

可参考已有的《媒体文化企业本体知识系统：建设与抽取流程说明》。该文档目前属于概念设计草案，教程中应将其作为待验证的建模起点，不将其描述为已经实施的系统。

代表性问题：

1. 某文化主题关联哪些作品、人物和机构？
2. 某作品有哪些版本，分别对应哪些素材文件？
3. 某人物以什么角色参与了哪些作品？
4. 两条同名人物记录是否指向同一个人？
5. 某项事实来自哪份材料、哪个版本、哪个位置？
6. 来源发生冲突时，系统当前采用什么结论，依据是什么？

## 3. 教学大纲

全课从[第 0 章「课程说明」](../00-course-overview/0-course-overview.md)开始，随后按第 1 至 12 章展开。[逐节教学大纲](本体论-逐节教学大纲.md)列出各章的文章安排、范例、思考、Q&A 与参考资料。

| 章节 | 节数 | 学习产物 |
|---|---:|---|
| 1. 现有系统中的知识组织方式 | 7 | 一张入库与查询对照图，标出原件、派生内容、索引与答案。 |
| 2. 为什么查不全、查不准，还会引用错来源？ | 4 | 一张失败样例表，分别记录应答集合、检索结果、最终答案和错误环节。 |
| 3. 从本体论到知识工程：何时建模，怎样回应业务问题？ | 4 | 一份人工推演结果和一份适用性判断，注明模型能解决的问题、所需前提与仍缺的证据。 |
| 4. 工程第一步：能力问题（CQ） | 3 | 一组可复测的 CQ，从这里开始保留回归样例。 |
| 5. 从 CQ 建模，并与已有模型整合 | 7 | 整合后的模型、概念复用与冲突裁决记录、旧新查询的预期答案。 |
| 6. 权威记录与受控词表：SSOT 和 SKOS | 3 | 一张权威记录责任表和一份 SKOS 角色词表。 |
| 7. 依据本体处理文档：从抽取、去重到正式记录 | 6 | 候选集、去重与审核决定，以及可查询的正式样例。 |
| 8. 用 SPARQL 回答 CQ，接入已有查询流程 | 4 | 查询文件、预期结果及按权限生成的带引用回答。 |
| 9. 用 PROV-O 追溯来源与更正 | 3 | 一条能从答案追到原文、也能从更正追到受影响事实的来源链。 |
| 10. 验证、测试与程序调试 | 4 | 一份分层测试报告及可以复现的错误修复过程。 |
| 11. 设计数据流，治理本体和事实的变更 | 3 | 一张运行流程图、责任表和一次可回退的变更演练。 |
| 12. 知识库第一版：交付与验收 | 3 | 可重建的知识库版本、留出原件的入库验收记录、问答评估与已知限制。 |

### 3.1 教学原则

**哲学概念落到具体判断。** 例如：“导演”是人物永久所属的类别，还是一次参与活动中的角色？同一作品换了文件格式，是否成为新作品？

**先建立正确样例，再扩大自动化。** 先手工构建少量模型和数据，明确正确结果，再引入 LLM 批量抽取。

**每章包含失败案例。** 例如同名人物误合并、把版本当成作品、数据校验通过但事实错误、来源撤回后仍被引用。

**区分不同层次的正确性。** 语法可解析、数据满足约束、逻辑一致、事实有证据、业务问题得到回答，应分别验证。

### 3.2 每章统一结构

1. 业务问题与学习目标。
2. 必要概念。
3. 建模选择及理由。
4. 可运行实验。
5. 反例与常见错误。
6. 验收方法。
7. 延伸阅读。

### 3.3 进阶选读

- 上层本体及其适用边界。
- 描述逻辑与形式化推理。
- 本体设计模式与跨领域复用。
- 本体对齐、实体链接与映射维护。
- 大规模知识图谱与推理性能。
- 本体辅助检索、问答与 Agent 应用。

以下清单区分教材、标准、工具和数据。免费阅读不等于允许全文转载；软件许可也不能自动用于其所有外部教材与数据。实际收入仓库时，应记录对应版本和许可。

### 4.1 优先整理顺序

1. **Keet 教材**：支撑本体基础与建模判断。
2. **LOT 模板**：支撑需求、范围和开发流程。
3. **W3C 标准与入门文档**：支撑语义和约束的准确性。
4. **RDFLib 与 pySHACL**：形成可运行、可验收的实验。
5. **Wikidata 小规模样本**：补充真实数据与实体对齐练习。
6. **WIDOCO 与 Ontology Development Kit**：完善文档、版本和发布实践。

## 6. 第一版最小交付范围

先完成一个小而完整的案例，再扩展章节和数据规模。

### 6.1 样例规模

- 约 30 个实体。
- 10 个业务问题与参考答案，见[逐节大纲的贯穿练习](本体论-逐节教学大纲.md#贯穿练习--给十道-cq-写下可以核对的答案)。
- 一份作品表。
- 几篇自行编写的说明文档。
- 一份模拟字幕。
- 一套本体、角色词表与主题词表。

留出一份未用于建模或调试的节目资料，供第 12 章独立验收。

### 6.2 必须覆盖的异常

- 同名人物不能直接合并。
- 同一作品存在多个版本。
- 两个来源给出冲突日期。
- 候选事实缺少证据位置。
- 结构校验通过，但事实与来源不符。
- 来源更正后，依赖事实需要重新审核。

### 6.3 完整学习流程

建模 → 导入 → 查询 → 校验 → 追溯 → 修正。

### 6.4 验收标准

1. 学习者可按照文档加载样例并执行查询。
2. 能力问题对应明确的查询或检查方法及预期答案。
3. 故意设计的无效数据能触发相应校验错误。
4. 正式事实能追到具体来源版本和证据位置。
5. 候选、未决冲突和正式结果能够区分。
6. 修正模型或数据后，可以重新执行检查并比较结果。
7. 关键建模选择有理由和反例，学习者能解释为何采用该设计。
8. 能从自然语言问题得到有权限依据和原文支持的回答；受限账号不会通过派生页面或引用看到受限事实。
9. 来源撤回后，派生结果可以定位和更新；重复导入不会新增重复事实或覆盖人工决定。
10. 另一位业务读者能依据概念定义对边界样例独立分类；固定规则，从未参与建模的原件启动入库，分别核对候选、审核决定、正式事实及查询答案，独立报告留出资料上的结果。

## 7. 教程的核心特色

把“如何认识和划分领域”与“如何维护可信知识”连接起来。学习者既能解释建模选择，也能拿出查询、证据和测试，验证知识系统是否回答了最初的业务问题。
