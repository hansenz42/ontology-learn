# 媒体作品署名与证据知识库 · 第一版交付设计

**状态：设计稿。** 仓库已有前三章正式课程、中文导论、角色入门课和 CSV 查询实验。下文的目录、操作和验收结果是后续实现的目标。十二章的节数与教学顺序以[逐节大纲](企业本体教程-逐节教学大纲.md)为准。

## 1. 交到谁手里，能用它做什么

编辑能查到林青在哪个发行版本以导演身份署名，并打开支持该结论的片尾位置。编目员能把一份新资料送审，说明为什么采纳、暂缓或撤回其中一条陈述。实施人员能从原始资料重建同一版本，复跑查询，并说明一次更正改变了哪些答案。

第一版的领域边界由大纲中的十道 CQ 确定。交付的本体负责作品、版本、媒体文件、人物、参与角色、拟邀与署名、证据及其关系。RDF 实例、词表、查询、程序和审核规则随本体一起发行，分别标注版本。资料使用自编的中文教学原件。

## 3. 一条记录怎样穿过整个系统

以 CQ-01“林青执导过哪些已发行作品”为例。原件 A 是《河流来信》发行版片尾，24:10 处写有导演林青；原件 B 是《城市回声》提案，第 2 页写有拟邀林青执导；原件 C 是该作品发行版片尾，46:20 处列出导演周明、访谈嘉宾林青。它们都进入资料库，分别支持不同陈述。

| 对象 | 必备信息 | 在例子中的作用 |
|---|---|---|
| 作品、版本、文件 | 各自稳定标识；版本指向作品，文件指向版本 | 转码可以产生新文件，查询作品数量时仍返回同一作品。 |
| 参与记录与拟邀记录 | 人物、角色概念、所属版本或提案对象、记录类型 | A 生成导演署名；B 生成拟邀；C 中两个角色各有一条署名。 |
| 证据片段 | 原件及版本标识、定位类型和值、原句、可见范围 | 时间码用于片尾，页码用于提案；两种定位都可以核对。 |
| 候选陈述与审核决定 | 陈述标识、抽取活动、证据、状态；决定另存审核人、理由和时间 | 未审核与未决记录可供编目员处理；正式查询只读取已采纳且当前有效的记录。 |
| 来源与变更 | 原件、抽取和审核活动、责任主体、派生关系、适用时间及记录时间 | 来源被更正后能定位受影响的正式记录，同时解释过去为何给出旧答案。 |

**查询验收样例。** 编辑提交 CQ-01，应得到《河流来信》及 A 的 24:10。换成“哪个项目拟邀过林青”，应得到《城市回声》及 B 的第 2 页。移除角色条件后，应能找到 C 的嘉宾署名。重复导入 A 不得重复计数；调用人没有任何可见支持证据时，回答限定在其可见范围内，不暴露片名、受限片段或引用。

## 4. 十二章怎样在同一个项目上累积

| 章 | 从哪里接手 | 本章留下什么，怎样交给下一章 |
|---|---|---|
| 1 · 组织知识 | 三份原件 | 固定资料清单、文件/表/片段/Wiki 对照和基线回答，供第 2 章逐项核对。 |
| 2 · 诊断问题 | 基线、人工参考清单 | 记录漏项、误项和证据错误，说明其发生在入库、检索还是解释环节。 |
| 3 · 引入本体 | 一道有证据的错题 | 用纸面模型修正答案，保留适用条件和仍缺的材料，形成试点范围。 |
| 4 · 定义 CQ | 业务人员的两个不同口径 | 十题验收清单。将拟邀与正式署名拆成不同问题，给出反例和未知项。 |
| 5 · 建模 | CQ、现有概念与旧表 | 第一版本体、手工实例和整合决策。回放旧报表和新 CQ，检查是否误把撰稿人算成导演。 |
| 6 · 权威记录与词表 | 模型里的角色和来源类型 | 发布角色标识和来源责任表，让抽取器、审核人、查询模板使用同一套定义。 |
| 7 · 抽取入库 | 原件、模型、词表 | 生成候选并审核入库，保留来源位置与裁决。跨页表丢失“拟邀”表头作为失败样例。 |
| 8 · 接入查询 | 已审核的图数据 | 跑通 CQ-01 与拟邀查询，返回作品和引用；留下查询模板和预期结果。 |
| 9 · 追溯来源 | 前两章已保存的证据和决定 | 用 PROV-O 表达来源链；更正一份片尾后列出应复核的答案。 |
| 10 · 验证调试 | 模型、数据、来源链与查询 | 建立分层测试，复现一次“结构合格但引用错片尾”的错误并定位。 |
| 11 · 运行治理 | 已通过回归的版本 | 固化入库、审核、撤回、重跑和回滚流程，保存新旧版本可重建的发行清单。 |
| 12 · 独立交付 | 冻结的规则、独立原件 | 接手人从原件重建并入库，分别提交入库质量、查询质量、维护成本与已知限制。 |

## 5. 第一版怎样验收

1. **从零重建。** 在干净环境按 README 一次完成加载、校验、测试和查询。固定样例部分不依赖在线模型；如采用 LLM 抽取，保存模型版本、提示词和输出，将重放与新的在线运行分别报告。
2. **核对模型。** 指定一个可推导的类型和一个不应推出的角色；检查图中实际结果。给同一作品增加转码文件，作品、发行版、文件计数应分别为 1、1、2。
3. **核对答案及证据。** 十道已知 CQ 按各自可见范围逐题核对。清单题列出漏项与误项，引用逐项回到原件；日期冲突且证据不足时须保留未决。
4. **处理变化。** 对同一输入重跑两次，已采纳事实不重复，人工决定不被覆盖。撤回唯一证据后，查出依赖它的事实、索引和 Wiki 页面，复核前停止作为已确认结果返回。用不同权限的两个身份核对输出。
5. **验收陌生材料。** 由业务同事封存未参加建模或调试的原件并独立标注实体、关系、证据与待核项。先冻结模型、词表和抽取配置，再从解析开始运行；评分标注不得作为抽取或审核输入。保留首次结果，分别报告漏抽、误合并、证据错位、错误采纳及最后的漏答和误答。
6. **形成发布决定。** 固定样例的必过项包括 CQ 预期、可复建、人工决定保留和权限隔离。对陌生资料，业务负责人与实施人员在开封前约定可接受误差及阻断条件；报告原始例数、失败位置与审核工时。若试验后修改规则，首次报告仍保留，独立复验需另选材料。

交接演示依次完成三个动作：问出一份有证据的作品清单，更正一次来源并解释答案变化，让另一位同事把一份陌生原件送到正确的正式或待核状态。三步各自留下查询结果、审核记录和测试报告。
